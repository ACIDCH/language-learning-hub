### 可执行命令

```bash
npm ci
npm run build
npm run release:report  # 输出可复核的未完成项；未完成时仍返回 0
npm run release:check   # 任一发布条件不符合便返回非 0；正式发布须此命令成功
npm run release:queue   # 按课时、教学专题、音轨输出未完成审校队列；可加 -- --json
```

基于现有零份人工签核证据，`release:queue` 当前列出 **639 个按课可追溯审核项**：156 个课程内容、327 个语法词汇专题、156 个逐段音轨；另有双设备恢复和桌面／手机实测两项验收。队列不是已审校证明，源文更改后仍须以 `release:check` 重新校验哈希与签核。正式 Worker 部署使用 `node ../../scripts/deploy-worker.mjs`（在 `cloudflare/learning-api` 目录执行），不得直接运行绕过门禁的 Wrangler 命令。

另有手动触发的 GitHub Actions 工作流 `Production readiness — evidence gate`，不会在门禁失败时执行部署。主发布流程必须在正式合并和生产发布之前调用相同的 `release:check`。

### 人工验收证据如何落库

位置：`config/release/evidence.json`。保持 `courseReviews`、`specialtyReviews`、`audioReviews`、`deviceRestore`、`browserAcceptance` 的原结构。

每课审核需提供 `courseId`、人类审核者 `reviewer`、`reviewerRole: human`、`status: approved`、时间 `reviewedAt`、实际复核证据定位 `evidenceRef`，及全部段落 `id / targetSha256 / chineseSha256`；源文或中译变化会自动使旧审批无效。

每专题同样使用相应专题 ID 和具备证据的独立人工审核记录。对于**自然录音交付模式**（默认 `audioDeliveryMode: verified_natural`），每课正式音轨需列全部段落 ID、目标语音文本哈希、录音资产 `assetRef`、来源授权 `rightsRef`、有效时长 `durationSeconds` 及真实试听 `humanListened: true`；不得拿 MyMemory、Chrome TTS、旧版本练习 MP3 或参考词汇录音冒充现行四段朗读。

对仅以**浏览器设备合成语音**提供朗读的正式个人学习版本，可改用显式 `audioDeliveryMode: device_tts`，但须提交 `ttsAcceptance` 的真实人工实机记录（常规签核字段之外，须 `passed`、`englishVoiceTested`、`frenchVoiceTested`、`desktopTested`、`mobileTested`、`fallbackTested`、`sourceAudioClaimsDisabled` 均为 `true`）。自然录音仍保持未验证状态；前端必须如实标明“设备 TTS，非原声录音”，缺少本机语音时有可用的文本阅读回退。**仅修改这个模式不会通过发布门禁**：全部课程、专题、设备恢复及浏览器验收条件不变。

双设备与浏览器验收另存真实结果；不要凭自动化通过便人工填入成功或创建虚假证据引用。上述记录没有建立前，`release:check` 明确返回失败。

## 2026-10-25 补充：跨设备并发保存完成到代码级防护

- 旧版本两个入口曾存在最后写入者覆盖风险：`src/useCourseProgress.ts` 的课程正文侧进度，以及 `src/CloudWorkspace.tsx` 的独立云端工作区。`cloudflare/learning-api/src/index.mjs` 曾容许不携带版本信息的覆盖型 PUT。
- 现已在两种入口的主课程 PUT 发送 `expectedUpdatedAt`。Worker 对首次创建使用无覆盖 INSERT；已有记录使用匹配 `updated_at` 的 PATCH；未携带版本条件的请求拒绝为 **HTTP 428**，更新冲突为 **HTTP 409**。基础课程的直接 Supabase 路径对应采用带版本过滤的 UPDATE 或不覆盖的 INSERT。
- 冲突情况下不自动丢弃本机草稿；需重新读取后人工选择云端版本或保留本机版本。跨课程和跨账户未完成请求的状态更新仍受隔离检查约束。
- 已增加 Worker 契约与 React 课程/云端工作区组件回归。**此项是模拟接口与 CI 下的验证，不是双真实设备在线验收结果。**
- 发布前必须使用两个真实设备反复测试“同时打开一课→分别编辑→先后保存→第二次收到冲突→重新读取并选择→刷新及重登”，分别涵盖 108 门主课程与 48 门基础课程。收集版本 SHA、两设备系统与浏览器、执行时间、失败网络日志及最终保存结果。不写入测试用户密钥到验收文件。
